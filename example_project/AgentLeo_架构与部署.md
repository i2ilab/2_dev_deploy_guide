# Agent Leo / deepsy.ai —— 架构与部署(🔴 进阶档,参考非必学)

> **看颗粒度,别照抄。** Agent Leo 把 112 位心理学大师做成 AI 分身,能 1v1 聊、也能拉几位"圆桌讨论"。它是"生产级"的样子——**账号系统、数据库、多 agent 都齐了**。放在这儿是让你**知道"再往上一档"长什么样**,不是要你现在做到。先把入门/中档做扎实,行有余力再看这篇。

## 一句话架构
**Next.js 14 全栈 + Supabase(数据库/登录)+ 后端代理调模型 + 多 agent 编排 + Railway/Cloudflare。**

## 前端 + 后端:Next.js 14 全栈(前后端一个项目)
- **Next.js 14 App Router + React 18 + Tailwind**:页面(首页 agent 墙、`agents/[slug]` 聊天页、群聊页)和后端接口(`api/chat`、`api/group-chat`)**在同一个项目里**。
- 白话:Next.js 这类"全栈框架"能同时装前端页面和后端接口,省得分两个项目——但对零基础**更重**,要理解 Server/Client 组件、路由约定。所以列为进阶。
- 后端 `api/chat/route.ts` 收到消息 → 从**文件系统**读该大师的 `SKILL.md`(人设,几百行)→ 调模型 → **流式(SSE)**把回复一点点吐给前端。**key 全在后端 env,前端拿不到。**

## 数据库:Supabase(什么时候才需要它)
- 用 **Supabase**(托管 Postgres + 登录 Auth + 权限 RLS)存:对话历史、群聊、用户资料、收藏。
- **关键设计:人设(SKILL.md)存在文件系统,数据库只存元数据**(名字、简介、指向哪个文件)——人设是"代码的一部分",跟着 git 走,不塞进数据库。
- 白话:**只有当你需要"记住用户是谁、跨设备看历史、多人账号"时,才需要数据库。** 你的课程项目**大概率不需要**——端到端示例连数据库都没有,照样能对话。别为了"高级"提前背上数据库的复杂度。

## ★ 最亮的两招
1. **persona-as-code(换文件 = 换专家)**:一个大师 = 一个 `SKILL.md`;想加一位,就加一个文件。**这正是你在 `0/1_claude_code_basic` 学的 agent.md + skill**,只是规模化了。
2. **多 agent 编排**:群聊有两种模式——
   - **Freeform 自由**:所有大师**并行**回答(`Promise.all`),各说各的,快;
   - **Roundtable 圆桌**:**顺序**发言,后面的能看到前面的,会互相回应/辩论。
   - 白话:多个 agent 怎么"排队说话"是**设计题**,不是玄学——决定了对话质量。

## 部署:Railway + Cloudflare
- Railway 跑 Next.js(`railway.json`,`npm start`,`/api/health` 健康检查)。
- **Cloudflare** 做 DNS 代理,帮国内访问更稳(deepsy.ai 免备案走这条)。
- 匿名优先:不登录也能聊(用浏览器本地的一个随机 session id 认人),降低门槛。

## 给你的两条可迁移经验(即使不做这么复杂)
1. **persona-as-code**:人设永远是文件(agent.md/skill),别写死在代码里——好改、好版本管理。
2. **先别上数据库**:能用静态 + 无状态后端解决的,就别上数据库/登录。复杂度是有代价的,按需增加。
