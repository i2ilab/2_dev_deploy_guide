# S3 · 前端接后端 —— 整体上线,手机能打开

> **目标**:让线上的前端连上线上的后端,处理好跨域(CORS),在**手机**上真正能对话。
> **前置输入**:S1 的前端网址 + S2 的后端网址。
> **产出物**:一个**任何人用手机就能打开、能对话**的完整应用。
> **配套 skill**:`/ship-golive`

## 先打个气:只差"把两个网址接上"

你已经有两个公网网址了:前端(Pages)、后端(Railway)。现在只做两件事:①告诉前端"后端在哪";②告诉后端"允许这个前端来找我"。接上,整个应用就活了。

## 新想法:CORS —— 浏览器的"门禁"

浏览器有个安全规则:一个网页默认**不能**随便调用别的域名的接口(防坏站偷数据)。所以当你的前端(`github.io`)去调后端(`railway.app`)时,浏览器会先问后端:"你允许 `github.io` 来调你吗?" 后端必须回一句"允许"——这就是 **CORS**。

运行示例的后端 `main.py` 已经加了 CORS 中间件,你只要把前端域名填进后端的 `CORS_ORIGINS` 变量就行。

## 操作步骤

1. **前端指向后端**:改前端 `index.html` 里的后端地址(运行示例里是 `BACKEND` 那一行):
   ```js
   : "https://你的后端.up.railway.app";
   ```
   保存、push,GitHub Pages 会自动更新。
2. **后端放行前端**:Railway → Variables → `CORS_ORIGINS` = `https://你的用户名.github.io`(你的 Pages 域名,别带末尾斜杠)。改完 Railway 会自动重部署。
3. **手机真机测**:用**手机浏览器**打开前端网址,发一句"有点紧张",看能不能收到回复。
4. **测危机拦截**:发一句"我撑不下去了",确认它**立刻**给出危机热线转介(这条底线必须在线上也生效)。
5. **测降级**:(可选)把后端暂时停掉,发消息,确认前端**不白屏**,而是给一句温和兜底 + 热线。

## 痛点对比

| 😌 简单·看不出必要 | 「我电脑上前后端都能连,肯定没问题」——本地是同一台机器不受 CORS 限制;一上线跨了域,浏览器直接拦,点发送没反应,你还以为是后端挂了 |
| 🔥 复杂·痛点凸显 | 上线后 90% 的"点发送没反应"都是 CORS 没配 / 后端地址写错。先看浏览器控制台(F12)有没有红色 CORS 报错,能省你两小时 |

## 常见坑

- **点发送没反应**:F12 看 Console。红色 `CORS` 报错 → 后端 `CORS_ORIGINS` 没填对。红色 `Failed to fetch` → 后端地址写错 / 后端没起来(先开 `/api/health` 验证)。
- **手机能开但发不出**:多半也是 CORS 或 http/https 混用(前端 https 不能调 http 后端)。
- **改了前端没生效**:Pages 缓存,等 1–2 分钟。
