# S1 · 静态展示上线 —— GitHub Pages(免费)

> **目标**:把你的**静态前端**(聊天页 / 展示页)推上 GitHub Pages,拿到一个任何人都能打开的公网网址。
> **前置输入**:一个 `index.html`(BUILD/B3 做的,或运行示例 `example_project/端到端示例_考前3分钟/frontend/index.html`)。
> **产出物**:一个 `https://你的用户名.github.io/仓库名/` 网址。
> **配套 skill**:`/ship-static`

## 先打个气:你已经在用 GitHub 了

前几天你已经把代码 push 到 GitHub。GitHub Pages 只是**多勾一个开关**,就把你仓库里的 `index.html` 变成一个公网网页。免费、不用服务器、几十秒生效。

## 新想法:静态托管 = 把文件夹变网址

GitHub Pages 不跑任何后端,它只是**把你仓库里的静态文件(HTML/CSS/JS/图片)原样发到公网**。所以它天生适合:
- 项目展示页 / 作品集 / 设计说明
- 你的聊天前端(前端本身是静态的,对话交给后端)

## 操作步骤(分步做,做完一步再下一步)

1. **建仓库 / 用现有仓库**:把前端代码(至少一个 `index.html`)push 到一个 GitHub 仓库。
   - 若前端在子目录(如 `frontend/`),把 `index.html` 放仓库根目录,或记住子目录名。
2. **打开 Pages 开关**:仓库页面 → **Settings** → 左侧 **Pages**。
3. **选来源**:Source 选 `Deploy from a branch`;Branch 选 `main`,目录选 `/ (root)`(或你的 `/frontend`)。点 **Save**。
4. **等一分钟**:刷新 Pages 页面,顶部会出现绿色的网址 `https://你的用户名.github.io/仓库名/`。
5. **验证成功**:用**手机**打开这个网址,页面能正常显示 = 成功。

## 痛点对比

| 😌 简单·看不出必要 | 「我把 html 发到群里让大家下载打开」——别人下载后路径乱、图裂、打不开;而且这不是"上线" |
| 🔥 复杂·痛点凸显 | 你要在答辩现场、用别人的手机、扫码就能打开——只有一个真实公网网址做得到;GitHub Pages 就是给你这个的最省事方式 |

## 常见坑

- **页面 404**:分支 / 目录选错,或 `index.html` 不在你选的目录。确认文件名就是 `index.html`(小写)。
- **图片裂开**:用了绝对路径 `/img/x.png`,改成相对路径 `img/x.png`。
- **改了没更新**:Pages 有缓存,等 1–2 分钟或强制刷新(Cmd+Shift+R)。

## 门禁检查(过了才进 S2)

- [ ] 拿到了 `github.io` 公网网址
- [ ] **手机**上能打开、显示正常
- [ ] 前端代码里 **没有任何 key**(`grep -rniE "sk-[a-z0-9]{16}" .` 为零)
- [ ] 链接发给一个没参与的同学,他能直接打开

## 思考题

> 现在你的静态页上线了,但点"发送"还没反应——因为它要连的后端还在你电脑里。
> 下一步 S2,我们把后端也送上线,给它一个公网地址。
