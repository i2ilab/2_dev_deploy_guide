## W0 · 总览:AI 时代,你为什么还要懂 web

### 开发这件事,已经变了

2026 年,约 **90% 的专业开发者每天都在用 AI 工具**写代码(Claude Code、Cursor、v0、bolt.new、Lovable……)。你说一句话,它生成一堆文件、跑起来、甚至帮你部署。你已经在做这件事了。

这带来一个新问题:**当 AI 替你写代码,你的价值在哪?**

答案是三件事——它们恰好是这份教程要给你的:

1. **看懂**:AI 生成了 `index.html`、`main.py`、`requirements.txt`……你至少要知道每个文件是干嘛的、大致在说什么。看不懂,你就只能盲目地点「接受」。
2. **会指挥**:你要能把需求说到点子上。比如出问题时,知道该说「改**后端**的逻辑」还是「改**前端**的样式」——说错了层,AI 就修错了地方。
3. **能排错**:程序一定会出错。白屏、404、CORS……你要看得懂报错大概是哪一类,才能把有用的信息喂给 AI 让它修。

> 打个比方:AI 是一个手很快的施工队,你是那个**看得懂图纸、拍板、验收**的人。图纸都看不懂,施工队再快,盖出来的也不是你要的房子。

### 类比:导演和摄制组

这门课反复讲一句话:**你是导演,不是码农。** 导演不用亲自扛摄像机、打灯光,但导演必须**看懂每个镜头、知道每个岗位在干嘛、发现不对能喊停**。这份教程,就是带你认全「摄制组的各个岗位」——前端、后端、模型、数据、部署——这样你才当得了导演。

## W1 · Web 是怎么运作的

在认识各层之前,先建一个**全局心智模型**:你打开一个网页,背后到底发生了什么?

### 一次请求的旅程(6 步)

你在浏览器地址栏敲下 `deepsy.ai` 按回车,到页面出现,大致经过这 6 步:

1. **输网址**:你在浏览器里输入网址(URL)。
2. **查地址**:浏览器问「DNS」——`deepsy.ai` 这台机器的真实地址(IP)是多少?**DNS = 互联网的通讯录**,把人好记的域名翻译成机器认的 IP 号码。
3. **发请求**:浏览器照着 IP,向那台**服务器**发一个「请求(request)」:请把这个页面给我。
4. **服务器处理**:服务器(后端)收到请求,准备好内容,发回一个「响应(response)」。
5. **传回来**:响应顺着网络回到你的浏览器。
6. **渲染**:浏览器把收到的 HTML/CSS/JS **画**成你看到的页面。

> 类比:你(浏览器)打电话到一家餐厅(服务器)。先查号码(DNS),打过去点单(请求),厨房做好(处理),菜端上来(响应),你摆盘开吃(渲染)。

记住这趟旅程——**报错时,你就能判断卡在哪一步**:是网址错了(第 1 步)、找不到服务器(第 2 步)、还是服务器自己崩了(第 4 步)。

### 客户端 vs 服务器:两个世界

这是**全教程最重要的分界**。上网这件事,永远有两边:

- **客户端(client)= 你的浏览器**。它在**你自己的电脑/手机**上跑。跑的是 HTML/CSS/JS,负责把界面画出来、接收你的点击。**它是公开的**——任何人打开你的网页、右键「查看源代码」,就能看到里面所有东西。
- **服务器(server)= 一台远处一直开着机的电脑**。它跑你的后端逻辑,负责保管秘密(比如 API key)、干重活、连接 AI 模型。**它是私密的**——用户看不到里面的代码。

回忆 `2_dev_deploy_guide` 讲过的**三层架构**:`前端(浏览器)→ 后端(服务器)→ 模型`。现在你知道前两层分别住在哪了:前端在**用户的浏览器**里,后端在**远处的服务器**上。

### HTTP、静态 vs 动态、域名

- **HTTP(S)**:浏览器和服务器对话用的「规矩」(协议)。你只需知道它就是「请求-响应」这一来一回。带 **S** 的 `https` 是加密版,现在的网站都用它。
- **静态网页(static)**:服务器只是把**事先写好的文件**原样发给你,不现算。适合展示页、作品集。→ 这种最简单,`GitHub Pages` 免费就能放。
- **动态网页(dynamic)**:服务器**现场生成**内容(比如调 AI 模型、查数据库)。你的能对话的 agent 就是动态的。→ 需要一个真正的后端(比如 `Railway`)。
- **域名(domain)**:`yourname.github.io` 这种人类好记的地址;背后靠 DNS 翻译成机器认的 IP。

**🤖 Claude Code 帮你做了什么**:处理所有 HTTP 请求、生成前后端、配好域名解析。
**👁 你要认得什么**:前端 = 浏览器 = 公开;后端 = 服务器 = 私密。你的项目 = 一个静态展示页 + 一个动态对话后端,正好一静一动。

## W2 · HTML:网页的骨架

从这一章起,进入**前端三件套**:HTML、CSS、JavaScript。用盖房子打比方——**HTML 是结构(墙和房间)、CSS 是装修(刷漆铺地板)、JavaScript 是电路(开关一按有反应)**。

### HTML 就是「用标签把内容装进盒子」

HTML(HyperText Markup Language)负责**页面的结构**:标题在哪、按钮在哪、输入框在哪。它用「标签(tag)」把内容一层层装进「盒子」。

看你运行示例 `frontend/index.html` 里真实的一段:

```html
<header>
  <h1>考前3分钟 · 小安</h1>
</header>
<form>
  <input placeholder="现在有点紧张…和小安说说">
  <button>发送</button>
</form>
```

三个词,你就看懂 HTML 了:

- **标签(tag)**:像 `<button>` 和 `</button>` 一对,包住中间的内容。`<` `>` 尖括号是标签的标志。
- **元素(element)**:一个完整的盒子,比如「一个按钮」「一个输入框」。
- **属性(attribute)**:写在标签里的设定,比如 `placeholder="…"`(输入框的灰色提示字)、`id`、`class`(给盒子起名字,方便 CSS 和 JS 找到它)。

> 类比:HTML 是一份**装修施工图**,标明「这里放一堵墙、那里开一扇门」。它只管**有什么、在哪**,不管好不好看(那是 CSS 的事)。

**🤖 Claude Code 帮你做了什么**:自动写好全部标签、嵌套结构、属性。
**👁 你要认得什么**:看到 `<button>`、`<input>`、`<form>` 大概知道是什么;能对 AI 说「在页面上加一个醒目的**危机求助按钮**」——它就知道要加一个 `<button>`。

## W3 · CSS:网页的外观

HTML 搭好骨架,页面会很丑(黑白、挤成一坨)。**CSS(Cascading Style Sheets)负责化妆和排版**——颜色、字号、间距、圆角、布局。

### 三件事看懂 CSS

```css
.btn {
  background: #C2410C;   /* 背景色:橙红 */
  color: white;          /* 文字颜色 */
  border-radius: 10px;   /* 圆角 */
  padding: 10px 18px;    /* 内边距(盒子内部留白) */
}
```

- **选择器(selector)**:先「选中」要装扮的盒子。`.btn` 表示「所有 class 叫 btn 的盒子」。
- **盒模型(box model)**:每个盒子都有**内边距(padding)、边框(border)、外边距(margin)**——记住有这三圈就够,具体交给 AI。
- **布局(layout)**:盒子怎么排。两种常见:**flex**(让盒子自动排队、对齐,最常用)和**绝对定位(position:absolute)**(指哪放哪,像贴便利贴)。
- **颜色**:用 `#1A365D` 这种**十六进制**表示(井号 + 6 位)。字号用 `px`(像素)。

> 类比:HTML 是毛坯房,CSS 是软装设计师——同一套房子,换套 CSS 就能从「冷淡专业风」变「温暖治愈风」。

**🤖 Claude Code 帮你做了什么**:写全部样式,还能一句话改配色/圆角/排版。
**👁 你要认得什么**:认得 `color`、`background`、`padding` 大概是什么;能说「配色换成**温暖治愈**的马卡龙色」「按钮做成圆角」——AI 就去改 CSS。

## W4 · JavaScript:让网页动起来

HTML(骨架)+ CSS(外观)之后,页面还是**死的**——点按钮没反应。**JavaScript(JS)负责行为和交互**:点击、输入、发消息、调后端。

### 三个基本功 + 一个关键动作

- **变量(variable)**:存东西的盒子。比如 `history` 存聊天记录。
- **函数(function)**:一段可以反复调用的动作。比如 `sendMsg()` = 「把用户的话发出去」。
- **事件(event)**:用户的动作**触发**函数。比如 `onclick`(点击时)、`onsubmit`(提交表单时)。
- **DOM**:JS 操作页面的方式(在页面上增删改盒子)。名字唬人,你只需知道「JS 靠它改变页面」。

看你运行示例 `index.html` 里真实的一段(简化):

```javascript
form.onsubmit = () => {       // 用户按发送时……
  const t = inp.value;        // 取输入框里的字
  sendMsg(t);                 // 调用发送函数
};
```

### 最关键的一招:fetch —— 前端向后端「打电话」

这是整份教程里前端最重要的一个动作。前端自己不会思考,它要**问后端**要答案。这个「打电话」的动作叫 `fetch`:

```javascript
const r = await fetch(BACKEND + "/api/chat", {
  method: "POST",
  body: JSON.stringify({ messages: history })   // 把聊天记录打包发过去
});
const data = await r.json();                     // 收到后端回的答案
```

一句话说清它干了什么:**前端把用户的话,发给后端的 `/api/chat`;后端跑 agent、回一段 `reply`;前端把 reply 显示成气泡。** 这就是你运行示例里 `sendMsg()` 做的事。

> 类比:前端是前台接待,自己不懂专业问题;遇到问题就打内线电话(fetch)问后台专家(后端),再把专家的回答转述给客户。

**🤖 Claude Code 帮你做了什么**:写好 fetch、错误处理、失败时的降级。
**👁 你要认得什么**:认得 `fetch` = 前端调后端;能说「后端**连不上时要有兜底提示,别白屏**」——这在心理陪伴产品里尤其重要(用户正难受时,页面不能崩在他脸上)。

## W5 · 数据怎么在网上传:JSON 与 API

前端(W2–W4)和后端要对话,得有**共同的语言**和**约定的窗口**。这就是 JSON 和 API。

### JSON:前后端之间的「普通话」

JSON 是一种**人和机器都读得懂**的通用数据格式,长这样:

```json
{
  "messages": [
    { "role": "user", "content": "我好紧张" }
  ]
}
```

它就是**「键: 值」的清单**——`"role"` 是键,`"user"` 是值。前端发 JSON 给后端,后端也回 JSON 给前端。你在 `1_claude_code_basic` 里已经见过它:你的 agent 输出协议就是 JSON,比如 `{"reply": "…"}` 或 `{"tool": "…"}`。

> 类比:JSON 是国际会议上的**同声传译**——前端说中文、后端说英文,但大家都把话翻译成 JSON 这门「普通话」,就能互相听懂。

**你只需认得**:大括号 `{ }` 是一个对象,里面是「键: 值」;方括号 `[ ]` 是一个列表。看到就不慌。

### API:后端对外的「菜单」

**API(接口)= 后端开放给外界的「点单窗口」。** 前端照着菜单点,后端照着单做。

- **端点(endpoint)**:菜单上的一道菜,用一个地址表示。你运行示例的后端开了两道菜:
  - `POST /api/chat` —— 聊天(把消息发进去,拿回复出来)
  - `GET /api/health` —— 体检(问「你还活着吗」,返回 `{"status":"ok"}`)
- **方法(method)**:怎么点。**GET = 取数据**(像查询),**POST = 提交数据**(像交表单)。
- **REST**:一套大家都遵守的「点单规矩」——用 URL + GET/POST 表达你要做什么。听到「REST API」,就理解成「一套规范的后端接口」即可。

### 状态码:后端给你的「回执」——看懂报错第一步

每次请求,后端都回一个**三位数字**告诉你结果。认得这四类,你就能读懂一半的报错:

| 状态码 | 含义 | 怎么办 |
|---|---|---|
| **200** | ✅ 成功 | 一切正常,拿到结果 |
| **400 / 401** | 你发的请求有问题 | 参数错 / 没权限(如 key 错) |
| **404** | 找不到 | 地址写错、页面或端点不存在 |
| **500** | 后端自己崩了 | 服务器内部错误,去看后端日志 |

**🤖 Claude Code 帮你做了什么**:设计好 API、处理 JSON 收发、返回正确状态码。
**👁 你要认得什么**:认得 JSON 长什么样、API 是「后端的菜单」、`/api/chat` 是你的对话端点;报错时能说清「是 **404** 还是 **500**」——AI 一听就知道往哪修。

## W6 · 前端框架:什么时候纯 HTML 不够用

到这里,你已经会看「纯 HTML/CSS/JS 的单页」了——你的运行示例就是这样一个 `index.html`。但真实的大产品(比如 Agent Leo)不是这么写的,它们用**框架**。这一章讲:框架是什么、什么时候才需要。

### 为什么要框架?纯静态何时够、何时不够

- **纯静态 HTML 就够(你的默认)**:一两个页面、一个聊天框、展示页、简单 demo。→ 一个 `index.html` + GitHub Pages,搞定。**别一上来就上重框架。**
- **该上框架了**:很多页面、要登录账号、要管很多「状态」、界面里有大量**重复的块**(比如一长串卡片)。手写纯 HTML 会很痛苦。

> 类比:纯 HTML 像**手写信**——一两封没问题;框架像**邮件合并/模板系统**——要发一千封个性化的,才值得上工具。

### React:把界面拆成可复用的「积木」

**React** 是目前最主流的前端库(2026 年最新是 React 19)。它的核心思想是**组件化**——把界面拆成一块块可复用的积木:

- **组件(component)**:一块可复用的界面。比如一个「消息气泡」,写一次,聊天里到处用。
- **props**:给组件传的参数。同一个气泡组件,传不同的文字/颜色,就显示不同内容。
- **state(状态)**:组件的「记忆」。比如输入框里的字、聊天历史;**state 一变,界面自动重画**——你不用手动去改 DOM。

### Next.js:React 的「全能版」

**Next.js** 是建立在 React 之上的**全能框架**(2026 年最新是 Next.js 16,自带更快的构建工具)。它比纯 React 多给你:

- **页面路由**:多个页面自动管理(不用手写跳转)。
- **前后端一体**:一个项目里既能写界面,又能写后端 API——**前端后端在同一个仓库**。
- **SSR(服务器端渲染)**:服务器先把页面渲染好再发给你,首屏更快、也更利于搜索引擎收录。

### 三个真实项目怎么选(看规律)

| 项目 | 前端技术 | 为什么 |
|---|---|---|
| **HEAI**(renben.ai) | 纯 vanilla HTML + D3 | 够简单,不需要框架 |
| **小智**(reading-bot) | Next.js(静态导出) | 内容较多,但仍导出成静态页 |
| **Agent Leo**(deepsy.ai) | Next.js 14 全栈 + 账号 | 最复杂:要登录、要多 agent、要数据库 |

看出规律了吗?**越复杂 → 越可能上 Next.js;够简单 → 纯 HTML 反而更省心。** 你的课堂项目,大概率纯静态 HTML 就够——需要了再让 Claude Code 帮你上框架。

**🤖 Claude Code 帮你做了什么**:判断该不该上框架,并把整套 React/Next.js 脚手架写好。
**👁 你要认得什么**:认得「组件、状态、框架」这几个词;知道**能静态就静态**的原则;听到「Next.js / React」不发怵,知道那是「给复杂前端用的工具箱」。

## W7 · 后端与服务器:藏 key、跑逻辑、连模型

前端讲完,来到**后端**——那台「一直在线接电话」的机器。

### 后端是什么

**后端(server)= 一个一直运行、随时等着接请求的程序。** 它的三大职责:

1. **藏 key**:API key 只能待在后端(前端是公开的)。
2. **跑逻辑**:跑你的 agent——也就是你在 `1_claude_code_basic` 造的那个 harness。
3. **连模型/数据**:替前端去调 AI 模型、读写数据。

### 用什么写后端:Node.js vs Python + FastAPI

- **Node.js**:用 **JavaScript** 写后端。好处是前端也是 JS,一种语言通吃;是 Next.js/Vercel 的原生路线。
- **Python + FastAPI**(**本课默认**):你在 `0_agent_basic` 已经会 Python 了,心智不用切换。**FastAPI 是把 Python 变成一个 web API 的最短路径**,而且 Railway 能自动识别、部署简单(HEAI/renben.ai 就是这套)。

### 看懂你的后端:`main.py` 其实就几行

你运行示例 `backend/main.py` 的骨架,简化后长这样:

```python
app = FastAPI()

@app.get("/api/health")     # 开一道"体检"菜
def health():
    return {"status": "ok"}

@app.post("/api/chat")      # 开一道"对话"菜
def chat(body):
    reply = run_harness(body.messages)   # 跑你的 agent
    return {"reply": reply}              # 回 JSON
```

认得三样,你就看懂了后端:

- `@app.get(...)` / `@app.post(...)` = **开一道菜(定义一个 API 端点)**。
- 里面的函数 = **收到请求时做什么**。
- `return {...}` = **回一段 JSON**。

而 key,是从 `os.environ`(环境变量)里读的,**不写死在代码里**——这样代码上传 GitHub 也不会泄漏。

> 类比:后端是餐厅**后厨**。菜单(API)贴在门口给客人看,但后厨里怎么做菜、用了什么秘方(key)、进货渠道(数据库),客人一概看不到。

### 数据与存储:先别急着上数据库

要不要「数据库」?**多数课堂项目:先不要。**

- **先用文件 / 内存**:够简单就别上数据库。你的端到端示例把情绪日记**存成一个文件**就够了。
- **何时才需要数据库**:要**长期记住很多用户**、要账号、要跨设备同步、数据量大。
- **Supabase 一瞥**:一个最省事的托管数据库(自带账号系统)。Agent Leo 用它存账号和对话。**但除非真需要,别过早引入**——它会让项目复杂一大截。

**🤖 Claude Code 帮你做了什么**:写好 FastAPI 后端、从 env 读 key、跑你的 harness、需要时接数据库。
**👁 你要认得什么**:后端 = 藏 key + 跑逻辑 + 连模型;认得 `@app.post("/api/chat")` 是「开一个对话接口」;知道「先别过早上数据库」。

## W8 · 工具链、看懂报错、安全红线

最后一块拼图:那些**黑框框、命令、报错**到底是什么。你不用记命令(Claude Code 会给),但要认得。

### 工程工具链:你会反复见到的几样

- **终端(Terminal)**:那个打字给电脑下命令的**黑框框**。像 `uvicorn main:app`(起后端)、`npm run dev`(起前端)都在这里跑。它不神秘,就是「用打字代替点鼠标」。
- **包管理(package manager)**:一键安装别人写好的「轮子」,不用自己造。**`npm`** 管 JS 的包,**`pip`** 管 Python 的包。`requirements.txt`(Python)、`package.json`(JS)就是「购物清单」,列出项目要装哪些轮子。
- **git / GitHub**:**git** 是代码的「存档系统」(可以回退到任何一版);**GitHub** 是放代码的云端仓库。你把代码 `push`(推)上 GitHub,`Pages`/`Railway` 才能拿去部署。

### 浏览器 DevTools:排错的「透视镜」(按 F12)

浏览器自带一个开发者工具,**按 `F12`(或右键→检查)** 打开。三个你会用到:

- **查看源代码**(右键→查看网页源代码):**验证前端有没有泄漏 key**。你能看到的,全世界都能看到——所以 key 绝不能出现在这里。
- **Console(控制台)**:JS 报错会以**红字**显示在这里。看到红字先截图,喂给 Claude Code。
- **Network(网络)**:看每个请求成没成。你能看到 `/api/chat` 返回的是 `200`(成功)还是 `404`/`500`(出错)——**排错神器**。

### 看懂四个最常见的报错

| 现象 | 大概是什么 | 怎么修(说给 AI) |
|---|---|---|
| **白屏 / 一直转圈** | 前端崩了,或后端没连上 | 看 Console 红字 + Network 有没有失败的请求 |
| **CORS 报错** | 后端没允许前端的域名跨域访问 | 后端 `CORS_ORIGINS` 加上前端网址 |
| **404** | 地址 / 端点写错了 | 检查前端 `fetch` 的 URL 对不对 |
| **500** | 后端内部崩了 | 去 Railway 看**后端日志**,找异常那一行 |

> **看懂报错 = 会指挥的一半。** 你能对 AI 说清「是**前端**白屏、Console 报了个红字,截图在此」还是「后端返回 **500**,日志说 XXX」——它就修得又快又准。抓瞎地说「它坏了」,AI 也只能瞎猜。

### 三条铁律(其中第一条是命)

1. **🔑 前端是公开的,key 只能待在后端。** 上线前用 `grep -rniE "sk-[a-z0-9]{16}"` 扫一遍前端目录,**必须为零**。
2. 后端连不上时要**优雅降级**(给兜底提示 + 危机热线),不能白屏——尤其心理产品。
3. 危机识别由**确定性代码**兜底,不只靠模型自觉(见 `2_dev_deploy_guide` B2)。

### 「看懂 + 会指挥」结课清单

读完这份教程,你应该能做到:

- [ ] 说得清**前端 / 后端 / 模型**各是什么、住在哪
- [ ] 看懂一个网页的 **HTML / CSS / JS** 三段分别管什么
- [ ] 知道 **fetch = 前端调后端** `/api/chat`
- [ ] 认得 **JSON、API、状态码 200/404/500**
- [ ] 知道**何时纯静态、何时上框架**(能静态就静态)
- [ ] 报错时会看 **Console / Network**,能对 AI 说清「哪一层、什么错」
- [ ] 记住那条铁律:**前端公开,key 只在后端**
