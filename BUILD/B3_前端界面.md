# B3 · 前端界面 —— 给你的 agent 一张能见人的脸

> **目标**:用三句话指挥 Claude Code 生成一个聊天网页,风格贴你的项目,带危机求助按钮,后端连不上也不白屏。
> **前置输入**:B2 的后端(本地能调)。
> **产出物**:`templates/前端提示词卡.md` 填完 + 一个本地能对话的前端页面。
> **配套 skill**:`/build-frontend`｜**样板**:`example_project/端到端示例_考前3分钟/frontend/index.html`
> **零 web 基础?** 先读 `web_basics/`(W2–W4 前端三件套 HTML/CSS/JS + W6 框架),就能看懂 Claude Code 生成了什么。

## 先打个气:你不需要会前端,你需要会"点菜"

一个聊天页,Claude Code 一次就能生成。你要做的是把"这道菜"点清楚:**做什么页、什么风格、连哪个后端**。然后逐句让它调,像捏橡皮泥。零基础也能做出像样的界面。

## 新想法:三句话提示词模板

给前端 AI 下指令,记住三句话:

1. **做什么页**:"一个聊天界面,历史消息在上,输入框在下。"
2. **什么风格**:贴你的项目定位——心理陪伴用"温暖、圆角、马卡龙暖色";评估工具用"专业、极简、冷静"。
3. **连哪个后端**:"把消息 POST 到我的后端 `/api/chat`,回复显示成气泡。本地连 `http://localhost:8000`,线上连我的 Railway 域名。"

心理/教育项目再追加两条(样板 `index.html` 都做了):
- **危机求助按钮**:"右上角加一个醒目的『我需要紧急帮助』按钮。"
- **优雅降级**:"后端连不上时,不要白屏,给一句安抚话 + 求助热线。"(小智 CompositeProvider 思想:AI 不可用,产品也不能崩在用户脸上。)

## 操作步骤(对 Claude Code 说什么 + 你检查什么)

1. 用上面**三句话**让它生成 `index.html`(参照 `frontend/index.html`)。
   - ✅ 你检查:本地起个静态服务(`python3 -m http.server 5500`),配合后端能真的一来一回聊天。
2. 说:"加危机求助按钮 + 后端失败的兜底提示。"
   - ✅ 你检查:故意把后端关掉,页面**不白屏**,给出兜底 + 热线。
3. 逐句捏风格:"气泡再圆一点""换成暖色""字大一号"。
4. **最重要的检查**:说:"确认这个前端里没有任何 API key。" 然后你自己也 `grep` 一遍(见 B4)。
   - ✅ 你检查:`index.html` 里只有后端 URL,**没有 `sk-`**。

## 痛点对比

| 😌 简单·看不出必要 | "命令行能跑就行,做界面是浪费时间。" |
|---|---|
| 🔥 复杂·痛点凸显 | 真实用户(一个考前焦虑的学生)不会开终端敲命令;答辩台上一个能点的页面胜过十行滚动日志。**没有界面 = 没有用户 = 没有 impact。** 而且做界面时最容易一时手滑把 key 塞进去——这一步同时是安全高危区。 |

## 门禁检查(过了才进 B4)

- [ ] 本地前端 + 后端能真实对话
- [ ] 有危机求助按钮
- [ ] 后端关掉时前端不白屏(有兜底 + 热线)
- [ ] 前端里**没有任何 key**(只有后端 URL)
- [ ] `前端提示词卡.md` 填完

## 思考题

> 你的界面风格,和你 agent 的"人设语气"一致吗?
> 一个温柔的正念 agent 配一个冷冰冰的深色极客界面,用户会信任它吗?
