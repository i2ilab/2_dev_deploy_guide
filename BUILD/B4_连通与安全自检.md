# B4 · 连通与安全自检 —— 跑通全栈 MVP,守住 key 铁律

> **目标**:把前端和后端接通,本地跑出一个完整的、能对话的 MVP;并做一次严格的安全自检,确认 key 绝不在前端。
> **前置输入**:B2 后端 + B3 前端。
> **产出物**:一个本地跑通的全栈 MVP + 通过"前端安全清单"。
> **配套 skill**:`/build-connect`

## 为什么这一步:接线 + 安检,一个都不能少

前后端各自能跑,不等于接得上——最常见的拦路虎是 **CORS(跨域)**。而且上线前**必须**做一次 key 安全自检:前端是公开的,一旦漏了 key,后果是真金白银的账单。这一步就是"通电 + 验安全"。

## 新想法:连通三件事 + 安全一条铁律

**连通**:
1. 前端的后端地址填对(本地 `localhost:8000`,线上 Railway 域名)。
2. 后端 **CORS** 允许前端域名(样板 `CORSMiddleware`;本地 `*`,上线收紧成你的 Pages 域名)。
3. 错误兜底:任一环断了,用户看到的是安抚话,不是报错/白屏。

**铁律**:🔑 **key 只能在后端,前端 `grep` 必须为零。**

```bash
# 在前端目录跑,结果必须是空:
grep -rniE "sk-[a-z0-9]{16}|openrouter.*key|authorization.*bearer" .
```
再顺手确认 `.env` 在 `.gitignore` 里、没被提交过:
```bash
git ls-files | grep -E "\.env$"     # 必须为空
```

## 操作步骤(对 Claude Code 说什么 + 你检查什么)

1. 说:"前端连本地后端,帮我把 CORS、地址都配好,让它们能对话。"
   - ✅ 你检查:浏览器控制台**没有 CORS 报错**;能一来一回。
2. 亲自跑上面两条 `grep`。
   - ✅ 你检查:前端 `sk-` 为零;`.env` 没进 git。
3. 走一遍 `checklists/前端安全清单.md` 和 `checklists/后端自检清单.md`,逐条打勾。
4. 手机上也开一下(和电脑连同一 WiFi,用电脑局域网 IP)——**很多用户是手机**。

## 痛点对比

| 😌 简单·看不出必要 | "我本地都通了,直接上线不就完了?" |
|---|---|
| 🔥 复杂·痛点凸显 | 不查 CORS,上线后前端一片"跨域失败";不查 key,某个同学图快把 key 写进前端 → 公开仓库被爬虫扫到 → 一夜刷爆额度。**上线前的这次 grep,是最便宜的保险。** |
